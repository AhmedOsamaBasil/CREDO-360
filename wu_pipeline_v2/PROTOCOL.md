# Output-bounded preparation, version 2

This amendment follows the failed first v1 preparation and the separately
published generated-source endpoint audit. It is an implementation correction,
not a change to the sixty-second scientific interval or quality/service contract.
Keep v1, its registration, failed video and all earlier records unchanged.
Publish this registration before invoking the real-source preparation.

## Exact permitted difference

Use the previously tested bounded command from wu_boundary: the v1 command
plus output-side `-frames:v 1800`. Preserve its input-side60s limit, all six
ladder settings, scale/fps/pixel filters, GOP, NVENC parameters and runtime.
The bound is a maximum, never padding or a relaxed frame-census criterion.
Every v1 packet, duration, keyframe, decoded-frame and remux identity check
remains active, including the complete parent and child census.

The unchanged original plan remains the source of all16clips,10eligible clips,
452directed pairs, source hashes, previous exclusions, contract and media
definitions. Expected totals remain60renditions,360parents,800recovery children
and452trace-label rows. Same48people recur; conditions remain separate.
No source retiming, replacement, pair cycling change, isotonic repair, free
buffer or resource allowance is introduced. No recovery controller runs here.

## Durable stage evidence

Record a stage-start event before phase sampling, reference sampling, encoding,
rendition validation, parent splitting, child splitting, map measurement and
trace aggregation. Save each completed phase diagnostic before encoding, each
completed rung's media record and tile map, and each completed trace label.
These private checkpoints improve failure diagnosis; they do not enable resume,
retry, optional stopping, partial-confirmation claims or clip selection.

An exception retains all files and records only exception type, last declared
stage, current clip/rung/parent/identity and exact registration digest. Do not
publish command stderr, absolute private paths or calendar timestamps. No
automatic retry/overwrite. A failed attempt has no completed-confirmation status.

## Measurement and evidence boundary

All numeric functions come unchanged from wu_pipeline.metrics. The original
fps1 reference remains primary, including the retained frame-rate conversion
phase caveat. Native MSE includes resizing/resampling/compression, not pure
same-source-frame compression error. Preserve every phase difference and
nonmonotone quality. Per-trace native means and rounded negative micro-MSE
must agree with the original independent scalar checks; never relax a failure.

All fresh labels are offline evaluation data, not current/future information
for a causal controller. Once derived, they are exposed for later research;
do not retune a method and call these same outcomes a fresh holdout. Physical
display timing, human QoE, recovery superiority and journal readiness are not
established by a successful preparation.

## Audit and release

Bind this method, the original full registration, source/runtime lineage and
both boundary-audit reports. Activation requires the new digest, the pinned
runtime, matching original assets and a new private directory. The digest
is an accidental-launch guard, not proof of author approval or publication.

A complete preparation is audited against the exact original clip plan and
full file hashes. Public evidence may contain media hashes/byte sizes, stage
metadata, source-ID labels and original derived tile-MSE arrays, never videos,
images, raw poses, demographics or private timestamps. Validate all output
paths inside the attempt directory before reading them. Independent label
rederivation from the bound maps and already validated private poses is a
separate audit; distinguish it from reproducing the hardware encoding.

A failed preparation is published only as a failed-attempt report and
sanitized stage/file census. Preserve completed diagnostics without inferring
missing results or declaring partial data a successful confirmation. A new
technical failure requires explicit diagnosis/versioning before another run.
